# Manager operator and handoff contract

## Entry points and UI

Command: `p2kesup [--role primary|backup] [--socket PATH] [--bundle DIRECTORY]`. Default role is primary; socket default matches `/run/pico2-kes-agent/management.sock`. Bundle selection remains verified/compatible/interactive. An authenticated candidate requires explicit tag or bundle selection for attended acceptance on a disposable host, after review, under the [distribution contract](distribution.md). `--help`, `--version`, `--version --json` are non-mutating. Invalid arguments exit 2. Nonterminal invocation refuses interactive work without mutation. Fatal availability/permission/local errors use the existing CLI classes 3/4/7; graceful quit is 0. A mutation failure is reported inside the UI and in its durable record, never hidden by a subsequent normal quit. Development builds identify as `development-unqualified`, not qualified releases.

`p2kesup upgrade [--version TAG | --bundle DIRECTORY | --resume ORIGINAL_PLAN_PATH]` infers the installed role. The resume path is absolute and mutually exclusive with version and bundle selection. The default selects latest qualified stable; explicit candidates require disposable-host review. It reviews and coordinates the complete signed host and firmware tuple, with attended physical firmware actions when needed; no arbitrary mixed tuple is authorized. An already installed tuple is a no-op. Interruption resumes only the original plan forward, with its recorded evidence and checks, never by rolling back persistent KES state or replacing the operation.

The coordinated primary upgrade durably inhibits daemon startup with an operation-owned persistent systemd mask before firmware transfer or partial host publication. Only the original operation can remove that gate after complete publication for approved validation. Validation failure re-establishes inhibition and attempts to stop the daemon. A proven pre-transfer cancellation with unchanged original installation can restore the original service; an ambiguous handoff cannot. Backup-role upgrades perform no device/service transition. A no-op reports the installed tuple only, not a live firmware check.

Screens: Overview, Pools/details, Software, Device, Host, Activity and the backup role. **Set up my Pico 2**, **Add a pool** and **Rotate KES key** guide their jobs; Activity selects original records for recovery. Up/down or j/k selects; Tab/Shift-Tab changes focus; Enter opens/reviews; Esc cancels/back; r refreshes; ? displays help; q quits from a nonapplying screen. Destructive confirmation names exact targets and consequences and defaults to No. Text labels carry health without color. Resize preserves selection; below 80×24 show minimum-size instructions and permit quit, not hidden confirmation. Escape untrusted terminal controls.

Opening any screen, navigation and refresh perform observations only. Confirmations expire on target/revision change. Mutations are serialized locally but concurrency elsewhere is handled by existing revision/operation checks, not assumed away. Busy/unavailable/incomplete status is distinct from empty/healthy. Redacted diagnostics contain public identities and error classes only, never node-service payloads, raw USB frames, private keys or passphrases.

## Workflows and authority

| Workflow | Existing surface / orchestration | Completion rule |
|---|---|---|
| Discovery/monitoring | Existing inventory/status plus [new observations](observations.md), local service/file inventory | Per-source age/evidence; all device pools and configured/effective bindings visible |
| First firmware installation | `python3 -I firmware.py first-install --bundle DIR --record FILE [--apply]` on an attended unambiguous BOOTSEL board | Authenticated firmware transfer and sole commissioning-daemon observation of selected compatible blank application; separate commission and pin |
| Commissioning | `device commission` in existing attended commissioning daemon mode | Explicit intended blank board, original receipt and no-clobber public enrollment record, reviewed pin/network/service configuration, normal-mode checks |
| Enrollment | `pool enroll` with validated public pool/network inputs | New incarnation from authoritative receipt; review binding; no node contact; 65th pool rejected |
| List/detail | `device inventory`, `pool list`, `pool observe` | Complete-vs-partial distinguished; unmatched device pools not hidden |
| Delete | `pool delete` | Exact pool/incarnation/revision confirmation, irreversible/fencing warning, original receipt; no unrelated target changes |
| Generate/discard | `key generate`, `key discard` | Exact generation/revision/preconditions; occupied stage or activation race preserves established rejection |
| Public key/backup export | `key verification-key`, `key export` | Explicit no-clobber destinations; encrypted artifact and public bindings retained; no primary plaintext key |
| Certificate | `certificate install` after off-primary signing | Matching public certificate validated; existing automatic activation rules, no new approval/archive gate |
| Recipient policy | `recipient set` with public record | Show recipient identity; result retained; only future artifacts change recipient |
| Reconciliation | `operation reconcile` with original receipt | Reuse original operation identity; never new-ID retry after uncertain submission |
| Service/config | Local approved host actions and existing daemon config parser/check | Working config preserved on invalid edit; observed service result, no implied node/pool readiness |
| Release/install/remove | [Distribution contract](distribution.md) | Authenticated compatible selection, reviewed ownership, retained data and post-checks |
| OTP | Foreground existing firmware tool, below | Original stage/readbacks/evidence, no inferred attestation |
| Backup role | Foreground existing local CLI, below | Restricted local output only after all evidence and memory checks |
| Producer hardening | Supplied drop-in plus approved systemd commands, below | Actual file install and command results; no runtime-policy audit |

For mutating CLI invocations, use structured argv with exact targets/revision and a new owner-protected receipt path; request `--json` for public results. The existing CLI owns receipt creation before submission, request identity and exit classes: 0 success, 2 invocation, 3 permission, 4 unavailable, 5 rejected, 6 uncertain, 7 local failure. If a subprocess disappears after its receipt is created, read/reconcile that receipt, even when no final stdout arrived. Never reconstruct a new request from a partial screen. Host maintenance records are separate because they track filesystem/service/firmware actions rather than device lifecycle operations.

Normal lifecycle actions obtain finite root admission bound to the caller UID, normal daemon socket, PID/UID and pinned device identity; the version-2 public admission expires after 120 seconds. Commissioning admission instead binds the restricted daemon and selected serial. The CLI receives paired `--expected-peer-pid` and `--expected-peer-uid` and checks the connected peer before sending bytes. Recheck admission after review; a changed authority expires approval. New commissioning also requires fresh compatible live blank admission. Recovery of an original `device.commission` receipt selects restricted authority by its original serial without requiring a blank device or a pre-existing normal pin; it reconciles only that original request.

## Setup inputs and service boundaries

Use existing config validation for operator-supplied or bounded read-only discovered systemd node-unit, environment, config and public genesis inputs, pool IDs, socket ownership and host policy. Show source paths/digests and exact agent-only diff; imported genesis files are root-owned 0644 under `/etc/pico2-kes-agent/genesis/<network>/`, source and destination digests checked, different existing bytes never clobbered. Known networks use their transition epochs; ask for custom network epochs. Never execute node scripts, contact node sockets, run Cardano CLI or infer forging. Missing or invalid public inputs block. Existing normal-mode agent preflight still expects `cardano-node.service` and host swap/sleep/dump/snapshot policy; do not change or bypass it.

Before commissioning or normal service start/restart, guided host-security review observes bounded swap/fstab/unit-source evidence, persistent masks, policy metadata and service limits. Explicit attended approval binds the exact evidence and external snapshot/crash-dump/private-custody assertions. The authenticated helper masks reviewed systemd swap activation and sleep targets, turns off only reviewed active swap, preserves fstab/unrelated policy lines, and atomically publishes `host-security.env` as root/service-group 0640. Normal mode uses existing producer hardening with reviewed active-only restart. Decline propagates cancellation, never success to a later lifecycle step. Root repeats readiness checks before service effects; UI approval alone does not authorize stale prerequisites.

Each effect has durable original-operation intent and readback. Activity resumes `host-security` forward with the original plan digest, refuses changed sources or unrelated artifacts, completes recognizable partial policy stages, and never blindly repeats an uncertain producer restart. A changed valid systemd InvocationID plus approved policy/limits can establish completed restart readback. Root/admin is trusted: this handles discovered systemd swap sources, not arbitrary future privileged activation. Unsupported sources fail closed. Ordinary operators approve through the UI rather than editing policy files.

Systemd may report `/etc/systemd/system/<unit>` as the fragment of a masked swap unit. Treat only that exact `FragmentPath` as a mask after validating root ownership and the exact `/dev/null` target; retain no-follow checks for ordinary sources and drop-ins. When a defective installed helper blocks recovery and therefore blocks updates, a separately approved signed bootstrap may resume only the original host-security operation. Bind the bootstrap manifest, candidate admission and protected running executable, then enforce the same maintenance lock, original ID/digest and other-pending-operation gates. Bootstrap recovery does not replace the selected manager or authorize a new security operation.

Wizard inspection obtains mode-bound peer authority through the installed read-only privileged admission helper for both normal and restricted commissioning services. It never inspects another user's protected process directly from the unprivileged UI. Commissioning authority binds the selected USB serial; normal authority retains the configured device pin. Check socket peer PID/UID on each observation and re-admit after inspection to reject daemon replacement, mode changes or identity changes.

For factory/BOOTSEL-only boards, offer the authenticated first-install handoff in the [distribution contract](distribution.md) before commissioning; no unavailable application serial/pin is inferred. A compatible blank application goes directly to blank admission, not a flash. Observe the selected application through one restricted commissioning daemon; ambiguous, wrong or unknown state blocks commissioning. Commission separately, review normal pin/config and stop restricted mode before normal service startup; never start a second USB owner. For an already commissioned board offer Keep with a matching trusted `device.json`, preserving existing config and pin when configured, or the explicit wipe below. Never auto-pin a self-reported identity. Interrupted first installation retains original recovery authority and is not retried as new work.

The destructive **Wipe board and start over** path requires an OTP-unlocked board, complete consistent fresh device/security/status/inventory evidence and no unresolved operations. Show affected pools, producer fencing and new-certificate consequences. Stop services; move config and agent state including journal into root-owned mode 0700 `/var/lib/p2kesup/archive/<operation-id>/` without clobbering; then invoke authenticated foreground `firmware.py erase-state --serial SERIAL --record FILE --apply` and verify its record and blank application post-state. Commission separately. Recovery from the original Activity record is forward-only: never repeat an uncertain or completed erase or automatically restore the archive. Locked boards offer Keep only; wipe is not an update or OTP recovery action.

Add a pool enrolls and binds before entering rotation. Recipient status is not invented from firmware: only a certain durable generation rejection specifically for a missing recipient triggers selection and installation of a public recipient followed by a fresh generate. Other or uncertain failures do not trigger this retry. Rotation calculates the absolute KES period locally with validated genesis timing and host UTC using daemon-equivalent arithmetic, exports public key and encrypted backup, and prints the offline signing command; it never runs Cardano CLI. Verify time and network inputs independently.

Root review displays the plan digest for records and asks `Proceed? [y/N]`; firmware displays the target and likewise asks default-no `[y/N]`. Attended TTY requirements, digest binding, fresh evidence checks and original records remain mandatory; no confirmations are scripted.

New first-install intent uses a root-owned `/var/lib/p2kesup/firmware/<32-lowercase-hex>.json` record. Both the manager and direct foreground tool require protected historical admission: existing device identity or selection, a nonempty or unsafe lifecycle journal, prior firmware records, incompatible maintenance history, or inaccessible evidence blocks a new transfer. Reopen the original owner-only record read-only; changing its filename cannot authorize a retry. The tool pins the verified BOOTSEL mount for transfer and leaves the original record uncertain if the mount detaches or changes.

Configuration review shows the exact existing and proposed bytes from the same
bounded snapshots used for approval. Root validation runs with the service identity
and filesystem sandbox before replacement. Original host plans reopen through
read-only inspection, never replay; interrupted first-install reconciliation names
the original operation and requires fresh selected-build/blank evidence from the
same attended board. Commissioning admission is immediately followed by the existing
CLI mutation, without an intervening prompt or background refresh. Failed privileged
handoffs remain visible for acknowledgement; successful admission does not pause.
Reviews too large for the terminal renderer's scroll range are refused rather than
allowing approval of hidden content.

Service actions use the unpublished internal `operation: start|stop|restart` payload, not the earlier `start` boolean. This is a clean internal cutover; old payloads are not silently migrated. Readback includes systemd `InvocationID` and job state: a pending job blocks reconciliation, and an unchanged active invocation cannot establish a completed restart. Service/configuration reconciliation observes the original record without replay.

## Secret-bearing backup handoff

`--role backup` is an explicit local role, not a remote mode or proof of host history. Before opening any private path or asking a passphrase, check the managed installation role, agent service/runtime/socket and known primary config/state evidence. Active or configured primary evidence refuses; inaccessible evidence blocks rather than being interpreted absent. Binaries without primary state are allowed. No operator override of contradictory evidence. Explain that the operator must use a separate host and that unregistered historical primary use cannot be proven absent.

For create/restore, explicitly approve finite root inspection of local `/proc` executable and role evidence before private-path forms and again immediately before the foreground child. Failure or inaccessible evidence blocks; this inspection does not read private paths or contact a daemon, device, socket or node.

Suspend raw mode and alternate screen; invoke the authenticated CLI in the foreground with inherited terminal stdin/stdout/stderr, never captured/teed. Existing command forms are `recipient create --out PRIVATE --public-out PUBLIC` and `restore --artifact FILE --recipient-key PRIVATE --device-identity PUBLIC --device ID --pool ID --incarnation ID --generation ID --verification-key PUBLIC --out NEW_FILE`. Passphrase is entered only by the CLI's existing secure interaction, never argv/environment/TUI history. Restore terminal UI after child exit and retain only public outcome/path metadata. Memory-policy rejection, wrong recipient, tamper, missing identity/binding evidence or output collision publishes no key.

Explain plaintext output custody, original certificate lifetime, no revocation of other copies and operator fencing obligations. Do not contact a daemon/device/node, import keys into Pico2, or transfer private material. Only the recipient public record is offered for explicit primary transfer. Diagnostics must not read restored output or private recipient bytes.

## OTP handoff

Use authenticated `python3 -I firmware.py` in the foreground. Available surfaces: `verify --bundle DIR`; `inspect --serial SERIAL`; `provision --distribution --stage prepare|enable|lock --serial SERIAL --bundle DIR --record FILE` (preview); same with `--apply` for one explicitly approved stage. Packaged `--distribution` binds the authenticated runtime/tool. Preserve physical transitions and direct tool prompts; never feed confirmations programmatically. The existing tool uses only the default management socket; provisioning refuses a nondefault configured management socket before any service stop or tool handoff. A daemon-mediated application observation may be required by the existing procedure: retain its foreground/two-terminal handoff without competing USB owners.

Require eligible blank target, exact serial/tool/bundle binding, supported hardware and required qualification before applying. Retain original protected record. Cancellation between stages preserves completed state and starts no next stage. An uncertain write blocks replay/advancement. Only original admitted pre-OTP `--resume` and read-only `reconcile-prepare --distribution --serial SERIAL --bundle DIR --record FILE --apply` are exposed as the existing tool permits; the latter flag does not authorize a repair write. Expose `erase-state` only through the explicitly attended wipe above, never in update or OTP recovery; never expose arbitrary record edits, generic reset instructions, signing-key prompts or automatic OTP in recovery. After locking, offer ordinary commissioning separately and state qualification limits.

## Producer drop-in exception

Offer bounded read-only discovered local node units for selection, allowing valid concrete unit names. Accept systemd escaped names and concrete instances, reject slash/traversal/control bytes, leading option syntax, empty template instances, non-service suffixes and names beyond systemd's unit-name limit. Validate before deriving paths or argv; do not shell-expand a name. Limit a single reviewed batch to 64 units.

After administrative approval, install the authenticated supplied `deploy/cardano-node-memory-hardening.conf` as `/etc/systemd/system/<unit>.d/pico2-kes-memory.conf`, using the same destination on repeats, preserving unrelated files. A pre-existing different file at that destination needs explicit replacement review. Use safe path ancestry and atomic file publication. Run `systemctl daemon-reload`. Query only selected units' running state to offer explicitly approved restarts; never start a stopped unit. If restart is deferred explain next-start/restart effect. File/command failure is reported accurately, including partial completion.

Recovery selects the original producer batch in **Activity**. Fresh public file/service readback is bound to its original operation and plan digest and reviewed again; changed evidence refuses. Replay requires explicit renewed approval of the original reload and any original try-restarts, adds no units or scope, and never starts stopped services.

Uninstall review binds the selected removal inventory to the registry digest and exact selected files/links, not just the registry alone. Original-record recovery binds fresh public readback to the original plan/digest; it does not stop services. Full removal retains registry provenance and authenticated source cache as well as state, pin, accounts, records and producer drop-ins. A later initial Install may restore the exact prior single-bundle tuple after completed full removal; mixed tuples are not silently reinterpreted. Neither removal nor recovery claims secure wipe or revocation.

Standalone producer hardening proves installed file and requested command outcomes, not runtime-policy certification. Guided host-security setup additionally checks configured service limits and the authenticated agent preflight. Uninstall retains/lists these drop-ins and does not restart producers.
