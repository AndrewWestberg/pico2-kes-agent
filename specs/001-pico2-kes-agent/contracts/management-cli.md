# Management, CLI and deployment contract v1

## Authority and transport

`pico2-kes-agentd` is the sole USB owner. `pico2-kes-agent-cli` service commands use a Unix stream management socket, default `/run/pico2-kes-agent/management.sock`. `--socket PATH` selects another configured endpoint; it never enables direct USB fallback. The same Unix owner/group/mode and directory access apply to all pool sockets. Any client with that access can manage and obtain all pools' current keys; separate endpoints do not create a stronger administrator role. Certificate integrity, generation identity and lifecycle checks still apply.

Management frames are u32 BE length followed by UTF-8 JSON, maximum 16,384 bytes. Version 1 rejects duplicate/unknown keys, invalid integers/hex, unsupported versions/actions and trailing JSON. Requests carry `{version,request_id,action,arguments}`; mutations additionally require `{operation_id,expected_revision}`. IDs are 16-byte lowercase hex, revisions u64 decimal. Daemon assigns/persists the device sequence before dispatch. Binary public values use lowercase hex; encrypted artifact transfer may use base64 in JSON with explicit decoded-length bound. No response contains an operational secret: use the existing per-pool node-service socket for current keys.

Responses carry `{version,request_id,outcome,result,error}` with one non-null result/error branch. Outcome is `success`, `rejected`, `pending`, or `uncertain`. Results include relevant pool/incarnation/generation/revision and operation ID. Errors include stable `code`, public `message`, target identity and retry/reconciliation advice. Human diagnostics go to stderr; `--json` emits one machine response to stdout. CLI file-output commands print only public identifiers/digests, never a key or decrypted-state preview.

Management admits at most 16 connections, one request in flight per connection and a total queue of 16 requests; node service admits two connections per pool (128 total) while guaranteeing the specified one-per-pool workload. Node queue capacity is one pending current read and one latest publication per pool; redundant subscribers are not an extra capacity guarantee. Use 5-second incomplete-frame/read/write idle deadlines. Full queues return `busy` before mutation admission; a timeout after admission is uncertain and must reconcile. Do not let management saturation block autonomous evolution or healthy current-key work.

## Attended commissioning

First enrollment is an explicit trusted-maintenance ceremony, not normal startup or pool enrollment. Stop the installed service and physically identify the intended board/USB connection running trusted attended-installed firmware. Run the same daemon as its normal service account with `pico2-kes-agentd --commission --config FILE`. Use the same socket permissions, runtime lock, USB ownership and public state directory as normal operation. In this mode only, configuration `device` contains the selected `usb_serial` without `id`/`identity_public_key`; `pools` must be empty. More than one matching USB device is `wrong_device`. The daemon exposes only the management socket and admits `status`, `device security`, `device commission` and `operation reconcile`; no pool sockets, key delivery or ordinary lifecycle mutations. The production systemd unit never enables `--commission`.

Run `pico2-kes-agent-cli device commission --usb-serial SERIAL --expected-revision 0 --receipt FILE --out DEVICE_RECORD`. SERIAL must equal the configured selection. The CLI uses the existing operation-ID/receipt rules; the daemon fsyncs a public intent before USB kind 10 with sequence 0. The storage classification and first-write rules are in [device-storage.md](device-storage.md#attended-first-device-commissioning). There is no reset/format option. Only a wholly verified blank state admits a new identity; exact committed retries recover that identity.

The version-1 public enrollment record contains `version`, `device_id`, `identity_public_key`, `identity_fingerprint` (SHA-256 of the 32-byte public key), `usb_serial`, `protocol_version`, `storage_version`, initial `device_revision`, `operation_id` and commissioning request digest. IDs/keys/digests use fixed-width lowercase hex. Verify a fresh hello challenge under the returned public key, then fsync the daemon result before receipt acknowledgment or CLI success. Atomically publish the public record without clobber and fsync file/directory; it contains no private key. Failure to publish the file does not undo device commissioning: preserve the receipt and recover with `operation reconcile --receipt FILE --out DEVICE_RECORD`. The optional `--out` is valid only for a successful commissioning result; collisions return `output_exists` without another mutation.

The operator trusts this initial public record because the physical connection, firmware and commissioning host were attended and trusted. Serial matching and a self-signature alone do not authenticate an unknown board; there is no factory attestation claim. Copy the record's ID/public key/serial into the normal owner-controlled configuration and archive the public record for backup-origin validation. Stop commissioning mode and restart normally; a fresh challenge against the installed pin is required before readiness. Never automatically replace an existing pin. A lost reply after commit reconciles the original operation, while partial/corrupt first writes return an actionable failure and require diagnosis rather than an erase.

Commissioning uses the same socket authority, not an administrator password or offline authorization. Starting the maintenance mode and editing deployment configuration use ordinary service-management permissions; no additional runtime role is introduced. Exit classes remain 0/2/3/4/5/6/7: `already_commissioned` or wrong selection is rejection (5), unresolved dispatched work is uncertainty (6), and storage/output failure is failure (7). Status reports public `commissioning_state: blank|committed|unavailable`; these are distinct from pool health states. Normal mode treats a blank device as `uncommissioned`, not permission to initialize.


## CLI command surface

Global options: `--socket PATH`, `--json`. Every mutating command takes `--operation-id ID --expected-revision N --receipt FILE`; it creates/fsyncs a public no-clobber request receipt before sending. A CLI may generate and print an operation ID when omitted, but must still persist it in the explicitly supplied receipt file before dispatch. On uncertain outcome retain the receipt and print the exact reconciliation command. IDs are not credentials. Successful replies update the receipt atomically without secret values.

| CLI command | Action and required arguments | Result / lifecycle rule |
|---|---|---|
| `status` | `device.status` | Intended identity, connectivity, firmware/storage versions, recipient fingerprint, public health, capacity and pending operation |
| `device commission --usb-serial SERIAL --out FILE` | `device.commission`; expected revision 0, ordinary operation ID/receipt; commissioning mode only | Explicit blank-device enrollment; return and publish the public enrollment record after durable completion |
| `device security` | `device.security`; empty arguments, normal and commissioning modes | Read-only public security policy report; no mutation ID, revision, receipt or command-specific flags |
| `pool list` | `pool.list` | Public records, page size <=16 with continuation cursor |
| `pool status --pool ID` | `pool.status` | Incarnation, active/staged descriptors, periods/certificate/publication state and actionable health |
| `pool enroll --cold-vkey FILE --network NAME` | `pool.enroll`; expected device-directory revision | Derive pool ID from cold key; create fresh incarnation, reject duplicate/65th pool; network must be configured. Daemon derives the public publication-order floor from retained deletion receipts, never from a CLI-supplied override |
| `key generate --pool ID --incarnation ID` | `generation.create`; expected pool revision | Create one staged generation, immutable encrypted artifact and auto-activation intent; reject occupied staged slot; return generation/vkey/artifact digest and retirement disclosure |
| `key verification-key --pool ID --incarnation ID --generation ID --out FILE` | `generation.public_key` | Public conventional KES verification-key envelope, no-clobber output |
| `key export --pool ID --incarnation ID --generation ID --out FILE` | `generation.artifact` | Exact retained encrypted artifact and retirement disclosure; retrieval is read-only, not another generation or encryption |
| `certificate install --pool ID --incarnation ID --generation ID --certificate FILE` | `generation.certificate`; expected pool revision | Verify binding/signature/counter/timing and commit; may automatically activate now, otherwise pending certification timing |
| `key discard --pool ID --incarnation ID --generation ID` | `generation.discard`; expected pool revision | Warn retrieval will be lost and external copies survive; explicit target must still be staged; active generation untouched |
| `recipient set --public-key FILE` | `recipient.set`; expected policy revision | Shared future-generation public recipient change; existing artifacts unchanged |
| `pool delete --pool ID --incarnation ID` | `pool.delete`; expected pool revision | Warn all pool operational keys/device artifacts will be removed; commit deletion and verified cleanup before slot reuse |
| `operation reconcile --receipt FILE [--out DEVICE_RECORD]` | `operation.reconcile` | Retrieve public durable result for exact original operation/digest; never start a new mutation. Optional no-clobber output only publishes a successful commissioning record |
| `recipient create ...` and `restore ...` | Local-only; [backup contract](backup.md) | Run without daemon/device, private recipient key remains on backup host |

`discard`/`delete` show the target generation(s) and retention warning, require interactive confirmation or `--yes` for noninteractive acknowledgment. This is accidental-deletion protection, not extra authorization. No acknowledgment is required for automatic activation/expiry/retirement. There is no standalone `activate`, plaintext import, arbitrary USB, firmware-update, signing or backup-readiness command.

Standard CLI exit codes: 0 success (including a reconciled success), 2 invalid invocation/input, 3 socket permission denied, 4 daemon/device unavailable before admission, 5 lifecycle/identity/certificate rejection, 6 uncertain/pending mutation outcome requiring reconciliation, 7 local I/O/crypto/storage failure. A rejected retry ID/digest is code 5, not a fresh operation. `operation reconcile` returns code 6 while genuinely pending; an originally rejected terminal result remains non-success. Generating a staged key is success even while it awaits a certificate; status reports that separate lifecycle state.

Stable error codes: `unsupported_version`, `invalid_input`, `permission_denied`, `busy`, `device_unavailable`, `wrong_device`, `uncommissioned`, `already_commissioned`, `socket_conflict`, `pool_unknown`, `pool_duplicate`, `capacity_exceeded`, `staged_occupied`, `target_not_staged`, `generation_mismatch`, `revision_conflict`, `operation_conflict`, `outcome_unknown`, `artifact_retired`, `certificate_invalid`, `certificate_regressive`, `not_yet_valid`, `expired`, `period_unavailable`, `period_regressive`, `entropy_failure`, `storage_failure`, `output_exists`, `artifact_invalid`, `recipient_mismatch`. Never label an I/O timeout as a clean rejection after dispatch.

## Read-only device security report

`pico2-kes-agent-cli [--socket PATH] [--json] device security` retains daemon-owned USB transport and the existing identity handshake. It is available in both normal and commissioning modes. It does not program OTP, update firmware, or independently attest hardware.

The existing response envelope's `result` has exactly these fields: `chip_revision` and `rom_version` (u8); `critical`, `boot_flags0`, `boot_flags1`, `debugen`, `debugen_lock`, and `density_bits_minus_one` (u32); `page2_lock0`, `page2_lock1`, `page63_lock0`, and `page63_lock1` (u8); `redundancy_ok` and `storage_blank_at_boot` (boolean); `bootkey0` (64 lowercase hexadecimal characters), `jedec_id` (6), `sfdp_header` (32), and `usb_serial` (16 ASCII lowercase hexadecimal characters, not double-encoded); `profile` and `stepping`.

`stepping` is `A2`, `A4`, or `unsupported`. `profile` is `unlocked` when secure boot is disabled, `rp2350-signed-msd-v1` only when the complete policy, authorized boot-key hash, page permissions, runtime debug locks and redundant copies pass, and `incomplete` otherwise. Missing public authority information cannot establish the locked profile. Read failures are errors, not zero-filled successful reports. Flash identity is the firmware's admitted fitted-flash measurement. Blankness covers the entire allocated state range at startup, not subsequent mutations. Unknown, duplicate, malformed or inconsistent response fields are rejected.

## Host configuration

Normal daemon invocation: `pico2-kes-agentd --config FILE`; `--check-config` validates only public configuration and exits without binding sockets or touching USB. `--commission --check-config` validates the restricted commissioning configuration without side effects. JSON version 1 normal-mode fields:

- `version: 1`, `device: {id, identity_public_key, usb_serial}`: attended pin, no automatic trust-on-reconnect.
- `socket_directory`, `socket_group`, `socket_mode: "0660"`, `management_socket`: all under the owner-controlled runtime directory; reject inconsistent per-endpoint policies.
- `state_directory`: owner-restricted public mutation journal/configuration; 64-MiB journal admission bound, checksummed records and fsync. No plaintext secret fields. Includes initial commissioning and completed deletion receipts; the latter supply a same-pool publication timestamp floor on re-enrollment, not a retained network period floor. Truncated uncommitted journal tails reconcile from device; corruption of acknowledged history fails closed rather than silently resetting.
- `networks`: named objects with exact genesis files/digests, network magic, local node socket, trusted `cardano_cli` executable path, era-history source and `max_context_age_ms: 30000`. Daemon queries public local node state every 5 seconds and derives/checks era-aware periods from trusted time. Fan each validated observation and synchronized publication-time sample out to exact pool/incarnation targets; durable period floors are independent per incarnation. A timeout, unsynchronized host, stale tip, mismatched genesis or regressive value withholds new time-dependent delivery.
- `pools`: initial socket bindings `{pool_id,incarnation_id,socket_path,network}`. Enrollment derives a stable default filename `<pool-id>.sock` in the shared directory; persist the resulting binding publicly before reporting host-side availability. Re-enrollment changes incarnation, never silently retargets an existing live connection. Unknown/duplicate/conflicting bindings fail with pool context.

All configured filenames and paths are validated before use; no client-provided path is forwarded into an executable shell. Dynamic enrollment updates the public binding registry atomically after device result reconciliation. A daemon crash between device enrollment and registry publication reconstructs the same mapping from its intent/receipt, not another pool. Socket mapping and registry failure affects readiness, not the already committed generation identity.

## systemd and operational memory boundary

Package `deploy/pico2-kes-agentd.service`, a udev rule giving only the daemon account USB access, and public example configuration. Unit uses a dedicated user, `RuntimeDirectory=pico2-kes-agent`, owner-controlled state directory, `UMask=0007`, `LimitCORE=0`, adequate `LimitMEMLOCK`, `NoNewPrivileges=yes`, restricted writable paths and restart-on-failure. Device access restrictions must allow the intended USB interface; do not copy `PrivateDevices=yes` blindly and break USB. Pool and management socket creation use identical group/mode.

Before secret handling, daemon locks required memory and disables dumping; failures are fatal to readiness. Zeroize buffers on every completion/error/disconnect. No plaintext persistent cache, diagnostic hexdump, secret error payload, swap or core dump is allowed. Node process protection, host swap/hibernation and snapshot policies are deployment requirements too. The conventional backup host explicitly permits the requested owner-only restored file; its weaker filesystem erasure is not the device's claim. Socket-authorized hostile commands and copies remain within the accepted trust model; no producer fencing is provided.
