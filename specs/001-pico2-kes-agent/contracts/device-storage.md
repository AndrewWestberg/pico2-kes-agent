# Device persistence and USB contract v1

## Flash layout and resource admission

The layout is a design for qualified raw NOR with 4,096-byte erase sectors and 256-byte program pages, not an observation about the attached board. Read JEDEC/SFDP and match the qualified part/geometry before enrollment. Reject unsupported fitted storage without initialization. No filesystem, hidden translation layer or encryption-only erasure claim.

The clean-cutover layout is storage format version 2. Version 2 adds the operation-handoff domain, pool discard recovery identity and configuration deletion recovery record. No version-1 migration or decoder fallback is implemented; a nonblank older/unknown format fails closed.

| Region | Half-open offsets | Bytes |
|---|---|---:|
| Firmware, image header and boot metadata | `0x000000..0x100000` | 1,048,576 |
| Device configuration A/B | `0x100000..0x104000` | 16,384 |
| 64 pool regions | `0x104000..0x304000` | 2,097,152 |
| Durable operation handoff A/B | `0x304000..0x308000` | 16,384 |
| Unallocated reserve | `0x308000..0x400000` | 1,015,808 |

Pool i starts at `0x104000 + i*0x8000`. Relative layout: secret snapshot A `0x0000..0x1000`, B `0x1000..0x2000`; immutable generation public objects A `0x2000..0x4000`, B `0x4000..0x6000`; reserved `0x6000..0x8000`. Public slots follow generation identity, not fixed active/staged semantics: activation changes references, not a secret-bearing object copy. Each public object holds one 4,064-byte tree, <=2,048-byte artifact and <=2,080 bytes of identity/integrity overhead. Both active+staged canonical states consume 1,216 bytes in one pool snapshot; the remaining 2,880 bytes include descriptors, certificates, authenticated headers and commit/clean marker pages. Encoding must prove this bound at maximum field sizes before hardware enrollment.

Configuration holds device identity/storage keys, recipient policy, slot/incarnation directory, the latest deletion terminal publication, and qualified format parameters within two 8-KiB banks. A separate pair of 8-KiB operation-handoff banks stores the exact pending or terminal managed mutation, result digest and next sequence, so reboot cannot reset sequence state or lose a committed result before host acknowledgment. Period floors belong to pool incarnations, bound to their enrolled network, not to a device-wide historical network registry. Certificate and publication high-water state also remains in pool snapshots, avoiding a global flash write on every pool evolution. Global management sequence tracks managed commands, not every autonomous KES update. No counter wraps; exhaustion fails explicitly. The reserve is not a license to add old-secret caches or an unqualified wear-leveling layer.

Firmware uses bounded fixed buffers and one current KES/tree workspace. Never cache all 128 secrets or 64 full trees. Budgets and timing targets are in [research](../research.md); qualify actual image size, stacks and framework overhead. Flash routines execute from SRAM with XIP/cache/core/interrupt handling required by the HAL and fitted part; invalidate caches before read verification. Flash operations may interrupt USB service, so bound worst-case stalls and retain host-side fair queues.

Installation is attended trusted maintenance using the RP boot ROM/normal tooling; no custom bootloader or A/B rollback contract. A single-image interrupted installation can require attended reflashing. Preserve the state partition during firmware-only installation; unsupported storage versions fail closed and require an explicit migration design, never automatic format/reset. No irreversible programming is authorized by this plan.

## Attended first-device commissioning

Normal startup, discovery and reconnect never initialize storage or learn a new identity automatically. The explicit daemon commissioning mode and CLI ceremony are defined in [management-cli.md](management-cli.md#attended-commissioning). Trust comes from the operator's physically controlled USB connection to the intended board running attended-installed trusted firmware. A serial selects a device; a self-signature proves key possession, not independent hardware or firmware attestation.

Before accepting USB `10 commission`, qualify the part and read-verify the complete allocated state region `0x100000..0x308000`. Classify it as:

- **Blank:** every byte is erased in both configuration banks, both operation-handoff banks and all 64 pool regions. Only this state admits a new commissioning operation. Blank configuration with residual pool or handoff bytes is not blank.
- **Committed:** a valid supported configuration COMMIT and body bind the device identity, empty initial directory, commissioning operation ID/request digest and initial sequence 0. Finish any required cleanup/CLEAN before exposing success. An exact retry returns the same public record; another operation is `already_commissioned`, never a reset.
- **Unavailable:** nonblank state without a valid authoritative commit, invalid/ambiguous committed data, unsupported format, or failed read/erase verification. Return `storage_failure` or `unsupported_version`; preserve the evidence and require attended diagnosis. There is no automatic erase/reinitialize or production reset command.

From blank state, generate the device ID and Ed25519/storage keys with device entropy in protected RAM. Write/read-verify the initial configuration, then its COMMIT; erase/read-verify abandoned secret material and wipe temporary seeds before CLEAN. Only then return the public enrollment record. A cut leaving the whole region still blank permits retry of the retained operation; a partial first write without a valid commit fails closed. A valid commit recovers the same identity even if its reply or host record was lost. Never report an uncommitted candidate identity as an enrolled device. Fault qualification must distinguish these outcomes rather than treat initial-write corruption as permission to format.

The commissioning ID/digest and public result remain in configuration after receipt acknowledgment so exact reconciliation is possible without inventing a new identity. The daemon journals/fsyncs the result before acknowledging sequence 0; subsequent managed commands begin at sequence 1. Recipient policy starts unset and generation fails until the shared public recipient is installed. No cold/KES secret is imported, no fuse is programmed, and no new administrator credential is introduced.

## Authenticated records and cleanup

Each snapshot identifies format version, pool/incarnation, monotonically increasing revision, parent revision/digest, enrolled network binding, optional absolute period floor, active/staged descriptors, current canonical states, certificate history, current publication descriptor and referenced public-object hashes. The publication descriptor contains kind `none|key|drop`, publication revision, optional generation ID, relative period/certificate binding for a key, and u64 POSIX-microsecond timestamp/high-water. Encrypt/authenticate the body using XChaCha20-Poly1305 with a fresh 24-byte random nonce and device storage key; headers are authenticated associated data. Separate domain keys for device configuration, operation-handoff and pool records using HKDF-SHA256. Device storage-key secrecy is not a physical-security claim: the accepted A2 threat boundary excludes malicious firmware and captured-flash rollback. Corruption detection is mandatory regardless.

COMMIT and CLEAN are fixed, authenticated, separately programmed marker records in reserved pages, bound to snapshot revision/digest. A partially programmed marker is never considered valid. Never program a page beyond the fitted part's qualified constraints. Public objects have authenticated digests in the secret snapshot. Erased bytes alone are not proof of a committed delete; deletion requires a committed tombstone/slot-directory transition and cleanup.

Before a managed pool/device mutation, commit its exact pending handoff record. After the lifecycle transaction becomes authoritative, commit the terminal public receipt before replying. Receipt acknowledgment commits the next sequence and clears the receipt. On reboot, an exact pending retry either completes the operation or reconstructs its already-committed result from durable lifecycle metadata; it never substitutes a rejection for a committed operation. Commissioning is the blank-state exception: its configuration commit contains the operation binding, allowing the terminal commissioning handoff to be reconstructed before USB service starts.

Transaction order:

1. Lock only the target pool's lifecycle; validate command, period context and expected identities/revision. Preserve the recoverable authoritative state.
2. Erase/read-verify candidate/public target regions before writing. Build new material in bounded RAM. For generation, produce immutable artifact and automatic-activation intent at period zero; erase seeds once no longer needed.
3. Program/read-verify new public object, then candidate encrypted snapshot. Verify MAC, references and complete payload before programming COMMIT.
4. Program/read-verify COMMIT. This successor is now authoritative, even if no response has been sent.
5. Erase/read-verify predecessor secret bank and any retired/orphan public objects. Wipe obsolete seeds, KES state and scratch. For activation, erase the predecessor snapshot containing the superseded active state. For discard, the successor retains unchanged active state but no discarded staged state.
6. Program/read-verify CLEAN; only now acknowledge the operation, release successor key state, publish a replacement/drop or report a slot free.

Recovery scans both banks and public-object references. An uncommitted candidate cannot override the valid old state and must be erased before delivery. A valid successor COMMIT cannot be rolled back because its CLEAN marker is absent; finish cleanup. A valid newer marker with unreadable body, conflicting parent chain, equal divergent revisions, invalid referenced public object or failed erase makes that pool unavailable. Do not fall back to an older valid body to hide ambiguity. If neither pool bank is valid, do not treat it as empty unless the authenticated device directory proves the slot was never enrolled or durably deleted.

Enrollment/deletion involve both slot directory and pool record: record a configuration intent with pool/incarnation and desired action, perform the pool transaction, then finalize the directory. Recovery resolves that intent idempotently before slot reuse. Deletion preserves a public tombstone until directory finalization; cleanup never frees a slot with ambiguous identity. Shared configuration corruption stops the device; isolated pool corruption does not.

Endurance qualification follows the service-life policy below. Batch catch-up in bounded slices without releasing intermediate obsolete state; never skip erase verification for speed. Exhaustion/erase errors become actionable unavailability, not secret reconstruction or weaker cleanup.

### Pool-incarnation period floors

The durable floor is the highest absolute period accepted for `(pool_id, incarnation_id, network_binding)`. USB context is addressed to that exact target. Validate the configured network parameters, lifetime, fresh session/sequence and lease; reject a lower period as `period_regressive`. A higher period must commit and become CLEAN in that pool's snapshot before context success or time-dependent key release. This may share a lifecycle transaction; otherwise charge the separate floor transaction to endurance. An equal-period refresh changes only volatile freshness/session state and performs no flash write. Expiry, replacement and staged discard retain the floor while the pool exists, even with no generation.

Recovery uses only the authoritative snapshot's floor, never a lower predecessor. Freshness is always invalid after reboot/reconnect; a persisted floor is not a clock. Catch up and clean every started certified generation before serving it. Pools sharing a network receive the same validated host observation but acknowledge independently against their own floors; a failed/quarantined pool does not supply an aggregate floor or prevent a healthy pool's progress. Shared configuration failure still stops the device.

Verified pool deletion removes that incarnation's period floor. Re-enrollment gets a fresh incarnation, no inherited slot floor, and must obtain fresh validated network context before any time-dependent operation. No record of retired network periods is kept. Required public operation receipts remain for retry reconciliation, not as secret-state or network-period history. This is the operator-selected minimal-metadata policy; encrypted key0 retention does not waive live-pool monotonicity or obsolete-secret cleanup.

### Device-owned publication ordering

The device owns the timestamp; the daemon never assigns or rewrites it. Fresh context carries a synchronized host sample `publication_time_us` (u64 POSIX microseconds) under the context's bounded lease. Each node-visible key/certificate/period change or explicit Drop commits one publication descriptor with `timestamp = max(sample, previous_timestamp + 1)`, checked for overflow. The publication revision is the pool revision of that visible change; metadata-only commits retain the descriptor unchanged. Repeated polls, receipt acknowledgments, reconnects and subscriber confirmations do not create publications or writes.

Commit the descriptor atomically with its key state/certificate or retirement and expose it only after CLEAN. USB `current` and public status return the stored descriptor; the daemon forwards its timestamp verbatim on V2. A lost reply after COMMIT/CLEAN reuses that publication. An abandoned uncommitted candidate never consumes a visible timestamp. Activation publishes the replacement directly, not an intermediate Drop. Neither pending receipt acknowledgment nor a full management journal blocks autonomous publication.

Key publication and period-driven expiry require fresh period context independently of timestamp ordering. Explicit operator deletion remains possible without period context: use a synchronized host sample supplied in the mutation envelope when available, otherwise checked `previous_timestamp + 1` for its terminal Drop. This logical ordering fallback never authorizes KES evolution. A pool that has never published a key needs no Drop. Timestamp overflow prevents a new publication and reports `storage_failure`; it must not wrap or invent a lower timestamp.

Before deleting a pool record, preserve its terminal public Drop descriptor and timestamp high-water in the durable deletion receipt; retain them until the daemon fsyncs the receipt. Directory finalization and slot reuse never erase the sole recoverable receipt. The daemon closes old-incarnation subscriptions, never retargets them, and can send the committed Drop only to the old binding. Re-enrollment of the same pool identity carries `publication_floor_us` derived from that identity's completed deletion receipts in the existing public journal; zero is permitted only when intact history proves no prior enrollment. The new incarnation's first publication exceeds that floor. A different pool reusing the slot inherits nothing. This is public retry/order metadata already retained by the journal, not a historical key cache or network-period registry. Missing/corrupt acknowledged history blocks enrollment rather than resetting ordering.

These v1 fields are coordinated pre-implementation contract refinements, not compatibility shims. Include their maximum encoded sizes, first-commissioning writes, context-floor commits and deletion-receipt costs in T043/T093; the 64-pool geometry and five-year/2× target are unchanged.

### Endurance acceptance policy

The operator-selected target is five years of service with a 2× endurance margin on every physical erase sector. Use a conservative horizon of 1,827 days (`H = 157852800` seconds). This is a qualification target, not a measured lifetime or approval of the complete quality-gate definition.

Qualify 64 enrolled pools with independent active/staged slots. Pin a public intended-deployment network/era profile for each pool separately from the controlled, possibly accelerated qualification network. No production credentials or production-node connection are needed to read these parameters. Derive an upper bound `P_p` on period boundaries over `H` from that deployment profile, including starting-phase uncertainty. For a constant period duration `d_p` seconds, use `P_p = ceil(H / d_p) + 1`; for changing eras, use a justified bound across the configured schedule. Let `L_p` be the minimum permitted generation lifetime over that schedule, with `1 <= L_p <= 64`. Budget `ceil(P_p / L_p) + 1` network-required rotations per pool in addition to the extra maintenance below. Measure workflow costs on disposable fixtures that cover the deployment profile's legal transition paths; do not extrapolate the accelerated fixture's event rate into a deployment lifetime unless it is itself the intended deployment profile. These are wear-accounting assumptions, not automatic generation or rotation commands.

| Workload component | Required service-horizon budget |
|---|---|
| Commissioning | One device enrollment, all 64 pools, and initial allocation/certification of 64 active plus 64 staged generations; include every constituent persistent transition |
| Evolution/catch-up | Up to `P_p` boundaries for each of the two generation roles per pool; use the worst legal evolution/expiry boundary cost and include catch-up cleanup rather than assuming one erase per missed boundary |
| Network-required rotation | `ceil(P_p / L_p) + 1` complete generation/export/certification/activation/retirement workflows per pool |
| Extra completed rotation | One per pool per 30 days: 61 workflows per pool |
| Extra generated-then-discarded replacement | One per pool per 30 days: 61 workflows per pool, including certification when it increases the legal worst-case cost |
| Shared-recipient change | One per device per 30 days: 61 changes |
| Pool deletion/re-enrollment | One per device per 30 days: 61 complete cycles, including cleanup and restoration of that slot's active/staged occupancy |
| Interrupted-operation recovery | One per device per day: 1,827 single-interruption/recovery cycles, including receipt reconciliation, abandoned candidates and cleanup retries |
| Background service | Continuous 64-pool subscriptions, `ceil(H / 5) + 1` polls per configured context/status stream, required publications, and reconnection of all subscriptions after each budgeted interruption; account for persistent writes caused by these paths and use the actual higher poll count if the pinned implementation polls faster |

Monthly counts use `ceil(1827 / 30) = 61`. Each complete workflow includes prerequisite commands and any discard/restaging needed to return to the starting occupancy through supported APIs; never reset storage or omit these erases to make the accounting fit. Use maximum legal costs across targets, active/staged occupancy, bank selection and persistent cut points, including shared configuration banks, pool banks, public-object regions, markers and scratch. A device-wide operation may repeatedly target the same pool or sector; do not average its wear across 64 pools. Lost replies/retries must include any actual erase cost rather than assuming idempotence makes writes free. Failed or interrupted erase attempts count conservatively as full cycles unless the fitted-part specification establishes a stronger safe bound.

For each physical sector `s`, record `R_s`, the manufacturer's guaranteed minimum erase-cycle rating under the qualified voltage/temperature conditions, with the exact part/datasheet source; `W_s`, a documented upper bound on wear already consumed, including flashing and qualification campaigns; and `E_s`, an upper bound on additional service-horizon erases. Compute `E_s` by summing the workload counts above multiplied by measured, conservatively bounded per-sector workflow costs. Include scheduled background writes and any additional implementation-induced transitions. Keep the cost/count calculation reproducible, with checked integer arithmetic. Initial commissioning is charged once: in `W_s` if already performed, otherwise in `E_s`.

Pass only if `2 * (W_s + E_s) <= R_s` for **every** sector. Report the limiting sector, its region, `R_s`, `W_s`, `E_s`, remaining cycles, and minimum achieved ratio `R_s / (W_s + E_s)`; only a sector with `W_s + E_s = 0` has no ratio constraint. Never substitute average bank wear, typical rather than guaranteed ratings, or a simulated erase count for fitted-device measurements. An unbounded transition cost, unknown prior-wear bound, missing rating/operating conditions, or unavailable network schedule makes endurance qualification inconclusive and blocks acceptance. Use a documented unused qualification part or a conservative documented wear history; elapsed age alone does not establish prior wear.

T043 produces a preliminary projection for implemented paths; P1/T093 must complete it for all paths on the acceptance candidate after accounting for the G8 and other campaigns on that physical part. Any later campaign adds to `W_s` and requires recalculation before acceptance. The five-year result is a projection from measured costs and rated limits, not a five-year physical soak test or a guarantee against arbitrary flash failure.

This workload is a service-life envelope, not a new API rate limit, reduced pool capacity, or a change to network-specific correctness. Faster test-network periods, more frequent valid management operations, further qualification campaigns, or different operating conditions require a recalculated projection; the original lifetime claim must not be reused unchanged. Malicious authorized wear-inducing commands remain within the accepted availability threat boundary, not a promise of unlimited endurance. A failed projection must not be hidden by weakening cleanup, reducing 64-pool capacity, requiring an A4 upgrade, or changing the target/margin after measurement without a separately approved policy change.

## USB transport

Use one vendor-specific interface with bulk IN/OUT and a stable device serial. Development uses the project's assigned/test VID/PID; production packaging requires a legitimately assigned VID/PID, never an invented third-party allocation. USB identity alone is not trust: before delivery the daemon verifies a challenge signature against the attended enrolled device Ed25519 key and exact device ID. Requests contain no administrator credentials. Host USB access is restricted to the daemon's service account; the spec does not require confidentiality against a physical USB tap or hostile kernel. Do not add an unaudited custom secure-channel protocol to claim it.

Frame: ASCII `PKA1` (4 bytes), protocol-major u16 BE (=1), message-kind u16 BE, request-number u64 BE, payload-length u32 BE, followed by canonical bounded CBOR payload and CRC32C of header+payload. Maximum payload 4,096 bytes; reject the declared length before allocation. CRC is corruption/framing detection, not authentication. Unknown major, opcode, duplicate/unknown fields, noncanonical CBOR or bad CRC rejects the request; reconnect resets framing. Every response echoes the request number and target identity. Ephemeral connection request numbers are not durable operation IDs.

| Kind | Request / response contract |
|---|---|
| `1 hello` | Host nonce 32 bytes; committed-device response includes device ID, identity public key, serial, protocol/storage versions, capacity, public commissioning state and Ed25519 signature over the canonical response plus nonce. Normal mode requires the configured pin; only attended commissioning mode may acquire the initial public key. Blank devices return `uncommissioned` with no invented identity/signature. No operational key before pin validation. |
| `2 status` | Optional pool ID; public device/pool/generation/receipt state and stored publication descriptor, paginated one pool at a time. No key bytes. |
| `3 context` | Exact pool/incarnation and network binding, validated absolute period/lifetime, session/sequence, freshness lease <=30 seconds and synchronized `publication_time_us`; persist a raised per-incarnation period floor before success, reject regression/incompatible parameters, and refresh equal-period leases without flash writes. |
| `4 mutate` | Action and durable management sequence/op-ID/digest, target identities, expected revision and bounded management arguments. Pool enrollment also binds the journal-derived `publication_floor_us` into the device request digest. Deletion may carry an optional synchronized publication-time sample. These exact device requests are journaled before dispatch and unchanged on retry. Return only committed-clean terminal result or explicit pending/error; deletion results include the terminal publication descriptor/high-water. |
| `5 reconcile` | Exact pending sequence/op-ID/digest; returns retained receipt, running state or explicit unknown/stale. Sequence 0 reconciles commissioning by serial and operation binding before normal pin installation. Never initiates generation or initialization. |
| `6 receipt_ack` | Sequence and result digest proving which public receipt daemon has fsynced; releases only the matching retained receipt. No backup-readiness meaning. |
| `7 current` | Exact pool/incarnation; returns snapshot revision and stored publication descriptor. A `key` result includes coherent generation, period, canonical 608-byte state and certificate only with valid context/CLEAN; `drop` is available only from explicit committed-clean retirement, not temporary unavailability. Never log the secret-bearing response. |
| `8 artifact` | Exact pool/incarnation/generation; returns retained <=2,048-byte artifact, digest and retention policy, or `artifact_retired`. |
| `9 public_key` | Exact pool/incarnation/generation; returns vkey and public descriptor or explicit unavailable. |
| `10 commission` | Exact selected USB serial, operation ID, canonical request digest, expected revision 0 and sequence 0; no host seed or secret. Initialize only verified blank storage; exact committed retry returns the original public enrollment record. Reject a different operation on an enrolled device as `already_commissioned`; partial/corrupt state is `storage_failure`, never reset. |

One USB request is in flight; the host retains at most one pending read per pool plus one management request. Firmware services autonomous lifecycle work cooperatively and provides public `pending` status rather than monopolizing a USB request throughout generation. Host scheduler alternates due pool reads/context/lifecycle work fairly. Firmware can mark a pool revision dirty in its status bitmap; daemon fetches/pushes the latest complete bundle, not a queue of secret historical bundles.

Error taxonomy matches [management contract](management-cli.md). I/O timeout is an uncertain mutation outcome; reconcile its identity. Context freshness expires on device reboot/session loss; a successful challenge does not establish valid time. New format/protocol major versions require caller migration and storage compatibility decisions before deployment; authentication/parse failure must never trigger an older decoder fallback.
